# SPEC 1.8.2 — UX/UI Overhaul

Status: implemented in 1.8.2
Scope: make quota and account state discoverable at a glance; no behavior change
to the manual-only switching contract

## 1. Problem

The 1.8.1 Activity Bar view was a tree. It was easy to miss, quota was buried in
a child node, and there was no quota signal in the status bar. Users could
reasonably say “I did not see the quota part”.

## 2. Goals

1. Show quota immediately after reload, without opening a submenu.
2. Make the dashboard feel like a product surface, not a debug tree.
3. Keep every switch manual and confirmed.
4. Preserve the TOS-safe boundaries: no auto-switch, no pooling, no proxy,
   no failover, no isolation.

## 3. Activity Bar webview

- Contribution type: `webview` (`antigravityAccountSwitcher.dashboard`).
- Header: active account, label/email, keyring chip, conflict chip,
  refresh button.
- Quota section:
  - live/cached badge and source;
  - groups (Gemini / Claude/GPT);
  - weekly and 5-hour progress bars with remaining % and reset countdown;
  - 429 banner when a local signal exists;
  - empty state with **Open Settings > View Usage**.
- Profiles section:
  - avatar, label, email, active/keyring-missing/incomplete chips;
  - **Switch** button uses the existing confirmation dialog;
  - keyring-missing profiles are disabled with a re-save instruction.
- Footer: Doctor, Diagnostics, Save current, Sign in.
- The webview posts commands to the extension host; it never touches tokens.

## 4. Status bar

- A second status bar item shows a compact Gemini weekly + 5-hour percentage
  (`$(pulse) 51% · 5h 82%`) and a full markdown tooltip.
- It updates on activation, window focus, dashboard refresh and quota command.
- Clicking opens **Antigravity Accounts**.
- If quota is unavailable: `$(pulse) Quota`, with a tooltip explaining the local
  fallback.

## 5. Discoverability

- Command: **Antigravity: Open Accounts Dashboard**
  (`workbench.view.extension.antigravityAccountSwitcher`).
- View-title buttons: refresh (force live quota), show quota, Doctor.
- One-time onboarding notification with **Open Dashboard** / **Later**.
- Status bar quota click opens the same view.

## 6. Security and correctness

- Webview HTML is generated by `dashboardHtml.js`.
- All dynamic values are HTML-escaped.
- CSP: `default-src 'none'; style-src 'unsafe-inline'; script-src 'nonce-…';
  img-src data:`.
- No external resources, no inline secrets, no token values.
- Dashboard actions use the existing extension functions, so all keyring,
  conflict and confirmation checks remain in force.

## 7. Performance

- Quota is cached for 60 s; the status bar and dashboard share the cache.
- The 5-second token watcher never calls `/usage` or the keyring.
- A manual refresh forces a live `/usage` call; the dashboard renders without
  blocking the token watcher.
- Dashboard HTML is a single local string; no network requests.

## 8. Acceptance criteria

1. After reload, the Activity Bar view shows an account header and quota bars.
2. The status bar shows a quota percentage when `/usage` is available.
3. Clicking the status-bar quota opens the dashboard.
4. The Open Dashboard command reveals the view.
5. Profile switch buttons still require the manual confirmation.
6. The dashboard renders safely with a profile label containing HTML.
7. The no-quota state shows Settings > View Usage.
8. Existing 58 JS + 60 Python tests pass; CI Ubuntu/Windows is green.

## 9. Non-goals

- New automatic account behavior.
- Quota-based rotation or failover.
- A separate web app or remote dashboard.
